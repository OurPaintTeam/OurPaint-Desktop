# Архитектура и API Sketch в Core

Архитектура привязок, API для инструментов и план реализации описаны отдельно в
[Snap: архитектура, API и план реализации](snap-architecture.md).

`core::sketch::Sketch` представляет один параметрический 2D-эскиз в локальных координатах.
Подключите `sketch/Sketch.h` и свяжите целевой модуль с `OurPaint::Sketch`. Сейчас `Document`
владеет Sketch через `std::unique_ptr`; другие владельцы могут использовать тот же API.
В будущем элемент модели, представляющий эскиз, может дополнить его опорной плоскостью
и преобразованием размещения. У Sketch нет идентификатора в документе, преобразования
в мировые координаты или формата хранения.

## Обязанности и владение

```text
Document / App / tools / render scene builder
                    |
                  Sketch
                    |
               Sketch::Impl
                    |
                DCMManager
```

Sketch напрямую использует DCM как единственный решатель. Его закрытый неполиморфный
Impl, определённый в Sketch.cc, владеет DCMManager и ресурсами модели. Sketch управляет
временем жизни реализации, распределением публичных ID, валидацией и политикой замены
состояния. Sketch.h не раскрывает типы DCM и дескрипторы решателя. Интерфейса бэкендов,
выбора адаптера, зеркала актуальной геометрии или индекса по типам нет. Временные записи
пакетных операций и значения запросов — независимые копии, а не ещё одна изменяемая модель,
служащая источником истины.

Impl хранит соответствия между публичными ID и внутренними дескрипторами, неизменяемые
виды сущностей, флаги вспомогательной геометрии, публичные определения ограничений
и метаданные владения ресурсами. Координаты берутся прямо из хранилища DCM. Определения
ограничений описывают уравнения, а не вторую модель текущей геометрии. Внутренние функции
работы с точечными ссылками находятся в sketch/PointElements.h и не раскрывают дескрипторы DCM.

Sketch отвечает за локальную геометрию, редактирование, ограничения, интерпретацию ссылок,
запросы, решение, диагностику и явный перенос состояния. Qt, рендеринг и графические API,
API операционной системы, выделение, выбор объектов в экранных координатах, жесты,
отмена/повтор, интеграция с буфером обмена, управление документами и хранение данных
остаются за его пределами. Благодаря этому Core сможет обслуживать будущую реализацию
на WebAssembly. Инструменты App не зависят от дескрипторов DCM.

Вызовы для одного экземпляра, включая константные запросы и уничтожение, должны
выполняться последовательно под контролем внешнего кода. Возвращаемые геометрия, векторы,
диагностика и снимки владеют своими данными и остаются действительными после последующих
изменений или уничтожения Sketch. Изменение возвращённого значения не меняет Sketch.
Независимые экземпляры владеют независимыми моделями и распределителями ID.

## Геометрия, идентификаторы и результаты

Координаты и длины используют единую систему единиц, выбранную владельцем; Sketch
не преобразует единицы измерения. Углы задаются в радианах. `SketchGeometry` — вариант
со следующими альтернативами:

| Значение | Поля и валидация при редактировании |
| --- | --- |
| `Point2` | Конечная `position` |
| `Line2` | Конечные и различные `start` и `end`; конечная положительная длина |
| `Circle2` | Конечный `center`; конечный положительный `radius` |
| `Arc2` | Конечные `center`, `start`, `end`; различные концы, положительные конечные радиусы, равные с относительным допуском `1e-9` |

Дуга идёт от начала к концу против часовой стрелки; её угловой охват строго больше нуля
и меньше полного оборота. Значения, полученные запросами до решения, могут иметь разные
радиусы после проекции на ограничения или неудачного решения. Запросы не исправляют
текущее приближение. Перенос состояния допускает разные радиусы дуги, но отклоняет
неконечную или вырожденную геометрию. `entityKind(geometry)` возвращает вид альтернативы варианта.

`EntityId` и `ConstraintId` — разные типы-обёртки над значениями ID из Core.
`get()` возвращает целое число; равенство и упорядочение сравнивают значения.
Неположительные ID недопустимы; положительные отсутствующие ID дают NotFound.
ID локальны для линии преемственности Sketch, не являются глобально уникальными
и не взаимозаменяемы между эскизами. Каждый распределитель монотонен и никогда не
использует повторно ID удалённых, очищенных или выделенных, но не вставленных объектов.
Обновления, решение и перетаскивание сохраняют идентичность. Снимки содержат верхние
границы выделенных ID, сохраняя историю удаления при переносе. Исчерпание диапазона
приводит к BackendFailure до переполнения.

`SketchEntity` содержит `id`, владеющее данными поле `geometry` и `construction`.
Признак вспомогательной геометрии — метаданные для потребителя, а не другое уравнение
или основание для исключения из запросов, подсчётов или решения. Вспомогательные функции
создания по умолчанию задают false. Обновления геометрии сохраняют этот признак,
если явно не передано необязательное значение.

`GeometryRef` определяет сущность и `SubElement`. Допустимые ссылки на точечные элементы
и порядок их выдачи внутри сущности:

| Вид | Точечные элементы |
| --- | --- |
| Point | `Whole` |
| Line | `Start`, `End` |
| Circle | `Center` |
| Arc | `Start`, `End`, `Center` |

Ссылки Whole на кривые обозначают кривые, а не точки. Концы и центры кривых — внутренние
ресурсы, принадлежащие кривым, а не самостоятельные сущности Point. Совпадающие координаты
или ограничения Coincident никогда не объединяют идентичность публичных ссылок.
`PointElement { GeometryRef ref; Vec2 position; }` предоставляет ссылки и текущие
координаты, а не топологию решателя или группы совпадения.

`Result<T>` содержит владеющее данными значение или `SketchError { code, message }`;
`Status` — это `Result<void>`. Перед вызовом `value()` или `error()` проверьте результат
через явное преобразование в bool; обращаться можно только к активной альтернативе.
Успешный `Result<SolveDiagnostics>` всё равно требует проверки `diagnostics.status`.

| Ошибка | Значение |
| --- | --- |
| InvalidArgument | Недопустимые геометрия, значение перечисления, ID, несовместимая ссылка, размер, смена вида, повторяющаяся цель или некорректный снимок |
| NotFound | Сущность или ограничение с положительным ID не существует |
| Unsupported | Отключённая операция или неподдерживаемая конкретная форма ограничения |
| BackendFailure | Ошибка DCM/ресурса или исчерпание идентификаторов/дескрипторов; обычное редактирование не гарантирует откат |
| SolveFailure | Зарезервированная категория; текущая реализация не использует её для численной несходимости |

Ошибки предварительной проверки InvalidArgument, NotFound и Unsupported оставляют модель
неизменной. Ошибка DCM после начала изменения может оставить частично применённое
редактирование. Result не является общим механизмом восстановления после исключений
выделения памяти или её нехватки. Ни один API не гарантирует откат при произвольных
системных сбоях.

## Интеграция выделения в настольном приложении

Picker и SelectionModel используют GeometryRef. Whole выбирает сущность целиком;
Start, End и Center выбирают её точечные элементы независимо. Выбор кривой не
выделяет автоматически её маркеры, а выбор маркера не выделяет кривую. Совпадающие
точки сохраняют разные ссылки.

Cpu2dPicker использует pointElements(All) для выбора точек и entities для выбора
кривых. Выделение рамкой включает каждую точку внутри прямоугольника и каждую
пересекающую его кривую. RenderSceneBuilder рисует обычные и выбранные маркеры
из pointElements и подсвечивает кривую только при наличии её ссылки Whole.
SelectionModel удаляет дубликаты ссылок, сохраняя порядок выделения.

CursorTool сохраняет позиции выбранных точек и курсора при нажатии. Кривые Whole
раскрываются в точечные элементы; пересекающиеся варианты выделения не дублируют точки.
Каждое движение передаёт абсолютные цели (исходные позиции плюс смещение курсора от
нажатия) одним вызовом dragPoints вместо updateEntities с последующим solve.
Цели остаются стабильными после проекции решателем, а частичное перетаскивание дуги
не требует передачи некруговой геометрии в updateEntity. Выбор только Circle Whole
меняет радиус и вызывает solve; Circle Center перетаскивает центр. Проверяется
статус сходимости. Отпускание кнопки и отмена очищают цели жеста; отмена не откатывает геометрию.
Рамка с Shift объединяет исходное выделение с текущими попаданиями, без накопления
попаданий от предыдущих положений рамки.

### Взаимодействие с ограничениями в App

Qt binder переводит события панели в значения ConstraintRequest, а UIController
передаёт их SketchEditor соответствующего документа. SketchEditor остаётся
координатором и не наследуется от IInteractionTool. Его обработчик клавиш
переводит сочетания для ограничений в те же запросы и передаёт остальные клавиши
активному инструменту. Escape сначала отменяет незавершённый ввод инструмента,
затем выходит из инструмента без незавершённого ввода.

ConstraintActions содержит общий путь подготовки и применения над заимствованным
Sketch. Подготовка не меняет модель: проверяет совместимость неполного выбора,
точное количество ссылок, числовые параметры, возможности Sketch и поддержку
готового определения. Готовое выделение применяется сразу без смены инструмента;
пустое или совместимое неполное выделение запускает ConstraintTool либо
DimensionTool. Неправильный/неоднозначный выбор и неподдерживаемые операции
завершаются без смены режима; подмножество большого выделения не выбирается скрыто.

ConstraintTool собирает объекты геометрических отношений, а DimensionTool
сохраняется как отдельный инструмент размеров. Оба заимствуют ConstraintActions,
picker и OverlayModel. Рабочие ссылки отделены от общего SelectionModel и
подсвечиваются через constraintRefs_. После успешного применения рабочий выбор
очищается, режим сохраняется для повторения. Линия целиком получает Length,
две точечные ссылки — Distance; концы линий считаются точками. Числовые запросы
используют единицы эскиза и радианы.

Отношения между линиями выбирают линии целиком; Equal/Tangent выбирают кривые
целиком без приоритета конечных точек. Coincident/Fix выбирают точечные элементы,
а Dimension сохраняет приоритет точек, чтобы конец линии задавал расстояние
между точечными ссылками.

ConstraintActions применяет Coincident с размещением Midpoint, проверяет вставку
и диагностику solve, при отказе возвращает управление. Транзакции, откат и
undo/redo пока не реализованы; отказ может оставить изменения модели. Кнопка
FixUnfix пока создаёт только точечный Fix, снятие фиксации не реализовано.
Кнопки отношений, отсутствующих в публичном Core API, пока ничего не выполняют;
Equal/Tangent дополнительно зависят от поддержки DCM. Визуальное активное
состояние кнопок остаётся под управлением UI-подмодуля независимо от результата
операции и активного режима редактора.

OverlayModel разделяет clearPreview() и clearSelection(). Очистка предпросмотра
инструмента сохраняет общее выделение; clear() явно очищает оба состояния.

## Создание, поддерживаемые возможности и совместимость исходного кода

| Функция | Результат и поведение |
| --- | --- |
| `defaultBackend()` | Всегда BackendKind::Dcm; постоянное время |
| `availableBackends()` | Владеющий данными вектор с единственным BackendKind::Dcm; ограниченная постоянная стоимость |
| `create(backend = defaultBackend())` | Result с unique_ptr, владеющим пустым DCM Sketch; неизвестное значение перечисления — InvalidArgument, исключения при создании — BackendFailure |
| `~Sketch()` | Освобождает Impl и ресурсы DCM; независимые возвращённые значения сохраняются |
| `backendKind() const` | Всегда BackendKind::Dcm; постоянное время, только чтение |
| `capabilities() const` | Независимая копия общих флагов поддержки; постоянное время, только чтение |
| `supportsConstraint(definition) const` | Status после общей валидации и предварительной проверки поддержки конкретной формы; без редактирования, выделения ID или решения |

Sketch нельзя копировать или перемещать; состояние нужно переносить явно. Методы
возможностей `supports(EntityKind)` и `supports(ConstraintType)` безопасно проверяют
массивы общих признаков поддержки и возвращают false для неизвестных значений перечислений.
Остальные флаги описывают обновление/удаление, решение, перетаскивание и диагностику.
Общая поддержка типа не заменяет проверку конкретной формы.

BackendKind содержит только Dcm. Методы выбора остаются для совместимости исходного
кода Core; App и UI не выбирают, не переключают и не показывают реализации решателя.
CMake всегда связывает Sketch с DCM без параметров и определений выбора решателя.

## Запросы сущностей и точечных элементов

Запросы доступны только для чтения и возвращают текущие, возможно ещё не решённые значения.
Коллекции сущностей и ограничений упорядочены по возрастанию публичных ID, даже после
импорта снимка с произвольным порядком. Точечные элементы упорядочены по возрастанию ID
сущности и в указанном выше порядке внутри сущности. Заимствованных представлений
или стабильных итераторов нет.

Пусть N — число публичных сущностей, M — публичных ограничений, K — выбранных сущностей,
B — входных элементов пакета, P — всех внутренних записей. Просмотр метаданных имеет
сложность O(N). Каждое чтение геометрии выполняет ограниченное число поисков в нативных
ассоциативных контейнерах, O(log(P + 1)). Поэтому массовые запросы геометрии стоят
O(N + K log(P + 1)), а не выполняются через поиск в индексе по типам. У каждой сущности
не более трёх точечных элементов.

| Функция | Результат, ошибки и стоимость |
| --- | --- |
| `entity(id) const` | Result со SketchEntity; требуется положительный существующий ID. InvalidArgument/NotFound/ошибки нативного чтения. O(log(N + 1) + log(P + 1)) |
| `entities() const` | Result с вектором всех значений SketchEntity, включая метаданные. Пустой результат успешен; время O(N log(P + 1)), память результата O(N) |
| `entities(kind) const` | Тот же результат с фильтрацией в Impl до чтения геометрии. Неизвестный вид даёт InvalidArgument; отсутствие совпадений успешно. Время O(N + K log(P + 1)), память результата O(K) |
| `points()`, `lines()`, `circles()`, `arcs()` const | Делегируют entities(kind) с теми же ошибками, владением, порядком и стоимостью. points() включает только самостоятельные сущности Point |
| `pointPosition(ref) const` | Result с Vec2; требуются существующая сущность и совместимый точечный подэлемент. Неположительный ID/несовместимый подэлемент даёт InvalidArgument, отсутствующая сущность — NotFound. Читает одну сущность: O(log(N + 1) + log(P + 1)) |
| `pointElements() const` | Result с вектором PointElement; объединение самостоятельных точек и подэлементов кривых, эквивалентное области All |
| `pointElements(scope) const` | Тот же результат; StandalonePoints, CurveSubElements или All. Неизвестная область даёт InvalidArgument. Impl просматривает метаданные и читает только совпадения, не создавая полную коллекцию сущностей: время O(N + K log(P + 1)), память результата O(K) |
| `pointElements(entityId) const` | Тот же результат для допустимых элементов указанной сущности. InvalidArgument/NotFound/ошибки нативного чтения как у entity(). O(log(N + 1) + log(P + 1)); не более трёх значений |
| `entityCount() const` | size_t, число публичных записей, O(1), без чтения геометрии/выделения памяти |
| `entityCount(kind) const` | Result со size_t, число публичных сущностей указанного вида; неизвестное значение перечисления даёт InvalidArgument. Просмотр метаданных O(N), постоянный объём дополнительной памяти |
| `constraintCount() const` | size_t, число публичных ограничений, O(1), без внутренних уравнений геометрии, опорных точек и внутренних ресурсов |

Ошибки нативных запросов могут давать BackendFailure; к исключениям выделения памяти C++
применяется общее ограничение, описанное выше. Запросы никогда не вызывают решение
и не обеспечивают корректность геометрии, даже если ограничения изменены после последнего
решения или текущее приближение некорректно.

```cpp
using namespace core::sketch;
auto queried = sketch.lines();
if (queried) {
    for (const SketchEntity& entity : queried.value()) {
        const Line2& line = std::get<Line2>(entity.geometry);
        // Use entity.id, entity.construction, line.start, and line.end.
    }
}

auto elements = sketch.pointElements(); // Standalone points plus curve elements.
if (elements) {
    for (const PointElement& point : elements.value()) {
        // Use point.ref for constraints/drag, point.position for display.
    }
}
```

## Редактирование геометрии и пакетные операции

Обычные изменения откладывают численное решение. Жёсткая проекция на ограничения фиксации
и совпадения может менять геометрию и соседние элементы, как описано ниже. Обновления
задают начальные приближения, а не жёсткие преобразования или групповое перетаскивание
средствами решателя.

| Функция | Результат и побочные эффекты |
| --- | --- |
| `addEntity(geometry, construction = false)` | Result с EntityId; проверяет геометрию, поддержку и доступную ёмкость, выделяет ID, вставляет нативные ресурсы и внутреннее уравнение дуги, если оно нужно |
| `addPoint(p)` | Тот же результат; Point2 с construction false |
| `addLine(start, end)` | Тот же результат; невырожденная Line2 с construction false |
| `addCircle(center, radius)` | Тот же результат; Circle2 с положительным радиусом и construction false |
| `addArc(center, start, end)` | Тот же результат; круговая Arc2 против часовой стрелки с construction false; обратите внимание на порядок параметров |
| `updateEntity(id, geometry, construction = std::nullopt)` | Status; только для того же вида сущности. Отсутствующее значение construction или nullopt сохраняет метаданные; явный bool также поддерживается. ID и ссылающиеся ограничения сохраняются |
| `setConstruction(id, construction)` | Status; меняет только существующие метаданные. Без повторной передачи/чтения геометрии, проекции, изменения уравнений или решения. O(log(N + 1)) |
| `removeEntity(id)` | Status; удаляет сущность, её внутренние ресурсы/ограничения геометрии и все публичные ограничения, ссылающиеся на Whole или любой подэлемент |
| `addEntities(std::span<const EntityCreation> input)` | Result с вектором EntityId; входы содержат геометрию и construction, по умолчанию false; порядок выходных ID соответствует порядку входов |
| `updateEntities(std::span<const EntityUpdate> input)` | Status; входы содержат ID, геометрию того же вида и необязательный construction. Отсутствующее значение сохраняет метаданные, существовавшие до пакета |
| `moveEntities(std::span<const EntityId> ids, Vec2 offset)` | Status; сдвигает текущие геометрические приближения на конечное смещение в локальных координатах через updateEntities. Сохраняет ID, construction и ограничения; радиусы окружностей не меняются. Пустой пакет успешен; недопустимые/повторяющиеся ID или некорректная результирующая геометрия отклоняются до изменения модели. Без численного решения; правила проекции DCM продолжают действовать |
| `removeEntities(std::span<const EntityId> ids)` | Status; удаляет цели по порядку вместе с их публичными ограничениями |
| `clear()` | Status; удаляет на месте все публичные сущности/ограничения и связанные внутренние ресурсы. Сохраняет Impl и верхние границы публичных ID; очистка пустого состояния и повторная очистка успешны. Без решения/замены состояния |

Создание отклоняет недопустимую геометрию с InvalidArgument, неподдерживаемые виды —
с Unsupported. Обновления дополнительно отклоняют смену вида и повторяющиеся цели
с InvalidArgument, отсутствующие ID — с NotFound, отключённое редактирование —
с Unsupported. Удаление и редактирование метаданных требуют положительных существующих
ID и поддержки соответствующей операции. Очистка clear поддерживается.
Нативные ошибки и исчерпание ёмкости дают BackendFailure. Одиночные операции используют
тот же путь валидации и изменения геометрии, что и пакетные.

### Валидация пакетов и границы гарантий при ошибках

Sketch проверяет весь вход до выделения ID или нативного изменения: корректность
геометрии, сохранение вида при обновлениях, существование ID, повторяющиеся цели
обновления/удаления, поддержку операций и доступную ёмкость публичных ID для создания.
Повторение геометрии при создании допустимо; у операции создания нет целевых ID.
Пустые пакеты успешно завершаются без нативного изменения или продвижения верхних границ ID.

Ошибки предварительной проверки InvalidArgument, NotFound и Unsupported никогда не
применяют пакет частично. Исчерпание публичных ID также приводит к ошибке до их выделения.
После предварительной проверки изменение идёт в порядке входных элементов
и останавливается при первой ошибке DCM. Отката при BackendFailure нет: предыдущие
изменения могут сохраниться, а сама неудачная нативная операция может иметь частичные
эффекты. Для восстановления запросите состояние модели. Создание выделяет ID для всего
пакета до нативной вставки; при неудачной вставке все они остаются использованными.
Результат с ошибкой не содержит списка успешно вставленных ID; оставшуюся публичную
модель можно проверить через entities(). Отдельной гарантии транзакционного восстановления
после исключений выделения памяти или системных исключений нет.

Пакетные операции не используют снимки, пересоздание Impl, постоянное зеркало точек
или журнал транзакций. Временные записи/дескрипторы занимают O(B) памяти.
Предварительная валидация создания стоит O(B); поиск повторяющихся целей обновления/удаления —
O(B log(B + 1)) плюс B чтений сущностей. Нативное редактирование включает затраты на
поиск дескрипторов и обслуживание графа; постоянное время на входной элемент не гарантируется.

DCM использует нативный updateFigures для смешанных обновлений. Он предварительно
проверяет дескрипторы, один раз определяет состояние фиксации/совпадения, применяет
входы по порядку и один раз синхронизирует совпадающие координаты. Режим GLOBAL не
выполняет численное решение. В линии Start предшествует End; в дуге Start предшествует
End, а End — Center. Для незафиксированной группы совпадения побеждает последнее
предложенное значение, в том числе при разных ссылках внутри одной входной геометрии.
Группа с Fix игнорирует предложения координат и сохраняет нативное поведение фиксированного
представителя/опорной точки. Противоречащие друг другу цели Fix обрабатываются явным
решением, а не валидацией пакета. Проекция может сделать кривые вырожденными,
а дуги — некруговыми.

Добавление/удаление используют прямые циклы Impl: внутренние концы
и центры находятся в исключительном владении, и ни одна из операций не выполняет
численное решение. Удаление просматривает публичные ограничения для каждой сущности;
в худшем случае это O(B M) проверок ссылок. После удаления DCM также может перестроить
кэши компонент/уравнений; Impl при этом не пересоздаётся.

Clear вызывает нативный clear у DCMManager для освобождения модели/кэшей и очищает
публичные записи. Его стоимость пропорциональна размеру внутренней модели/кэшей.
При успехе счётчики становятся нулевыми. Clear не гарантирует откат при ошибке DCM.

```cpp
const std::array<EntityCreation, 2> input{{
    {Line2{{0, 0}, {5, 1}}, false},
    {Circle2{{8, 3}, 2}, true},
}};
auto added = sketch.addEntities(input);
if (added) {
    // Several edits/constraints can precede this one numerical solve.
    auto solved = sketch.solve();
    if (solved && solved.value().status == SolveStatus::Converged) {
        // Consume solved geometry.
    }
}

if (added) {
    // Metadata edit without geometry resubmission or solving.
    Status changed = sketch.setConstruction(added.value()[0], true);
    if (!changed) { /* Handle changed.error(). */ }
}

Status cleared = sketch.clear(); // Same Impl; IDs stay above consumed values.
if (!cleared) { /* Inspect the current model and cleared.error(). */ }
```

Для пакетов обновления используйте EntityUpdate{id, geometry, std::nullopt}, чтобы
сохранить construction, или явный bool; вызовите updateEntities(updates), затем
проверьте его Status перед единственным явным решением.

## API ограничений

ConstraintDefinition содержит type, refs, необязательное значение размера value
и необязательное fixedPosition. Ссылки должны существовать и соответствовать следующим
формам. Ограничения с двумя ссылками требуют различных GeometryRef, даже если координаты
совпадают. Только размерные типы принимают value; только Fix требует конечного
fixedPosition. Неожиданные или отсутствующие обязательные поля дают InvalidArgument.

| Ограничение | Ссылки и значения |
| --- | --- |
| Coincident | Две ссылки на точечные элементы |
| Horizontal, Vertical | Одна линия целиком |
| Parallel, Perpendicular | Две линии целиком |
| Distance | Две ссылки на точечные элементы; конечная неотрицательная длина, включая ноль |
| Length | Одна линия целиком; конечная положительная длина |
| Angle | Две направленные линии целиком; конечный неотрицательный угол в диапазоне `[0, pi]` радиан |
| Equal | Две линии целиком или две круговые кривые (Circle/Arc) целиком |
| Radius, Diameter | Одна круговая кривая целиком; конечная положительная длина |
| Tangent | Линия и круговая кривая целиком или две круговые кривые; контракт внешнего касания сейчас не поддерживается DCM |
| Fix | Одна ссылка на точечный элемент с явно заданным конечным fixedPosition; цель сохраняется после редактирования, неудачного решения и переноса |

| Функция | Результат, ошибки, побочные эффекты и стоимость |
| --- | --- |
| `supportsConstraint(definition) const` | Status; проверяет поля/ссылки, затем поддержку конкретной формы. InvalidArgument/NotFound/Unsupported/ошибки нативных запросов. Не более двух чтений сущностей; без изменения |
| `addConstraint(definition)` | Result с ConstraintId; выполняет предварительную проверку и проверку ёмкости, выделяет ID, устанавливает уравнения/внутренние ресурсы. Без решения; выделенный ID остаётся использованным после ошибки DCM |
| `updateConstraint(id, definition)` | Status; требуются существующий ID, допустимая поддерживаемая замена и возможность обновления. Сохраняет публичный ID; может заменять только преобразованные уравнения/опорные точки, без численного решения |
| `removeConstraint(id)` | Status; требует существующего положительного ID и поддержки удаления; удаляет уравнения/внутренние опорные точки без численного решения |
| `constraint(id) const` | Result со SketchConstraint, владеющим определением. Неположительный ID даёт InvalidArgument, отсутствующий — NotFound. O(log(M + 1)) плюс копирование определения ограниченного размера |
| `constraints() const` | Result с вектором SketchConstraint по возрастанию ID; пустой результат успешен. Копирование/память результата O(M), без решения |

Изменения ограничений могут обновлять нативные связи между эквивалентными элементами
и состояние фиксации; выполнение уравнений обеспечивается проекцией геометрии
или явным решением. Стоимость изменения зависит от обслуживания графа и преобразованных
ресурсов. Unsupported при предварительной проверке оставляет состояние неизменным;
BackendFailure не гарантирует откат обычного редактирования. В этой версии нет пакетного
редактирования ограничений или запросов ограничений с фильтрацией.

## Решение и перетаскивание

solve() возвращает Result с SolveDiagnostics. Если возможность не поддерживается,
ошибка возникает до изменения состояния. Ошибки DCM могут давать BackendFailure.
Текущая реализация вызывает solve у DCM, но в рамках существующего TODO безусловно
устанавливает статус успешного результата в SolveStatus::Converged без проверки
сходимости. Решение сохраняет публичную топологию/ID, но может менять координаты,
не заданные ограничениями. Неудачная попытка может сохранить своё приближение,
включая некорректную/вырожденную геометрию; запросы возвращают это состояние.

drag(const DragRequest&) выполняет один синхронный шаг к конечной целевой позиции для
ссылки на точечный элемент, стремясь получить наилучший возможный результат.
Неконечная цель, неположительный ID или несовместимый подэлемент дают InvalidArgument;
отсутствующая сущность — NotFound; отключённое перетаскивание — Unsupported.
Результаты/ошибки соответствуют solve. Координаты меняются без изменения публичных ID
и топологии или создания постоянных ограничений; неудачные приближения могут сохраняться.
Цель — предпочтение, а не гарантированная координата. В Core нет сеанса жеста,
отмены или истории. После drag не нужно вызывать solve: drag уже выполняет решение
с предпочтением выбранных координат, а обычный solve такого предпочтения не имеет.
Нужно проверять и Result, и diagnostics.status.

dragPoints(std::span<const DragRequest>) проверяет весь набор до изменения модели
и передаёт все цели одним пакетом DCM. Повторяющиеся GeometryRef отклоняются
с InvalidArgument; разные совпадающие ссылки остаются разными и могут конкурировать
(в DCM побеждает последняя цель незафиксированной группы совпадения).
Пустой набор ничего не меняет и возвращает диагностику по умолчанию без решения
эскиза. Кривые Whole вызывающая сторона раскрывает в точечные элементы.
Это совместное перетаскивание точек с учётом ограничений, а не жёсткий перенос группы.

Необязательные degreesOfFreedom, conflictingConstraints и redundantConstraints
при отсутствии означают недоступность данных, а не ноль степеней свободы (DOF)
или пустую диагностику. Диагностика использует публичные ID ограничений.
Сама по себе несходимость не доказывает наличие конфликтов. Стоимость решения
и перетаскивания определяется численной сходимостью, подготовкой графа и структурой
уравнений; фиксированной линейной оценки времени нет.

DCM инкрементально использует свой менеджер со стабильными адресами. Дуги DCM сами
по себе требуют внутреннего уравнения равенства радиусов. Диагностика DOF, конфликтов
и избыточности для всего эскиза не предоставляется, поскольку она не учитывает свободные
и исключённые переменные. Нативное перетаскивание не сохраняет информацию о сходимости;
solve может сообщать об успехе для противоречивых систем фиксации. Impl использует
updatePoints в режиме DRAG для всего пакета целей, затем восстанавливает режим GLOBAL
без повторного решения, в том числе при исключениях. Как и solve(), dragPoints() сейчас
безусловно сообщает Converged после успешного нативного вызова. Существующая функция
проверки невязок/геометрии не используется ни в одном из путей формирования результата.
Потребители по-прежнему проверяют Result и diagnostics.status, однако текущее значение
Converged не доказывает выполнение ограничений. Нативные уравнения углов DCM также
используют радианы.

## Снимки и замена состояния

| Функция | Поведение и гарантии при ошибках |
| --- | --- |
| `snapshot() const` | Result со SketchSnapshot: независимые текущие сущности/ограничения и обе верхние границы ID, учитывающие удалённые ID. Без решения; стоимость запроса геометрии плюс копирование O(M), память результата O(N + M) |
| `replaceState(snapshot)` | Status; подготавливает новый DCM Impl, проверяет/вставляет состояние и заменяет Impl только после полного успеха. Без неявного решения |
| `switchBackend(kind)` | Метод совместимости; Dcm успешно обрабатывается без действий, неизвестное значение перечисления — InvalidArgument. Не меняет модель и не выполняет решение |

Верхние границы ID должны быть неотрицательными и охватывать все положительные уникальные
ID. Геометрия должна быть конечной/невырожденной; при переносе допускаются разные радиусы
дуги. Проверяются определения/ссылки ограничений и поддержка DCM.
InvalidArgument, NotFound, Unsupported или сообщённый BackendFailure сохраняют исходную
модель и Impl; подготовленный кандидат уничтожается. Верхние границы ID
целевого распределителя становятся максимумом текущих и импортированных границ.
Импорт может восстановить старые ID, явно переданные снимком: это намеренное восстановление
состояния, а не повторное выделение ID. При импорте несвязанного состояния владелец должен
управлять линией преемственности.

Только замена временно создаёт ещё один DCM Impl. Она использует O(N + M) памяти
для подготовки, чтения геометрии и затраты на нативную вставку; линейное время
реконструкции не гарантируется. Численные кэши, контекст документа и схема хранения
не переносятся. Неконечные/вырожденные приближения после неудачного решения могут быть
отклонены без уничтожения источника.

## Возможности DCM

| Операция | DCM |
| --- | --- |
| CRUD для Point/Line/Circle/Arc; метаданные, подсчёты, clear | Поддерживается |
| Пакетные операции с геометрией; запросы точек/области запросов | Поддерживается |
| Coincident, Horizontal, Vertical, Parallel, Perpendicular | Поддерживается |
| Distance, HorizontalDistance, VerticalDistance, Length, Angle, Fix для точечных элементов | Поддерживается |
| Equal для длин линий/радиусов круговых кривых; Radius/Diameter | Не поддерживается |
| Tangent для кривых целиком | Не поддерживается |
| Обновление/удаление ограничений; решение; перетаскивание точечных элементов | Поддерживается; ограничение текущей диагностики сходимости описано выше |
| Снимок/замена | Поддерживается для допустимых определений DCM |
| DOF всего эскиза, диагностированные конфликты/избыточность | Недоступно |
| Проекция обновлений по Fix/Coincident до решения | Нативная жёсткая проекция |

Sketch не поддерживает произвольный Fix для кривой целиком, жёсткое перетаскивание
целой сущности/группы, совпадение точки с кривой или транзакции редактирования.
DCM ограничивает набор ограничений преобразованиями
с установленной семантикой.

## Оценка архитектуры и предложения по дальнейшему развитию

Вычислительная интерпретация и прямое владение DCM остаются в Core.
Фильтрация/подсчёты используют метаданные и не читают координаты несовпадающих элементов.
Общие правила ссылок обслуживают валидацию ограничений/перетаскивания и запросы точек;
только Impl преобразует их в дескрипторы DCM. DCM использует нативные смешанные пакеты
и прямые циклы добавления/удаления.
Дублирующая актуальная геометрия, постоянное зеркало точек, индекс по типам, политика UI
или зависимость не добавлены. Существующие потребители в App сохраняют совместимость
на уровне исходного кода, включая обновления метаданных с явным bool.

Сохраняются намеренные ограничения: копирование/просмотр при запросах, повторные просмотры
ограничений при удалении и отсутствие отката при ошибке DCM. Ёмкость публичных ID проверяется заранее;
исчерпание нативной ёмкости и нативные ошибки могут возникнуть после начала редактирования.
Существующий TODO в solve/drag оставляет диагностику сходимости незавершённой.
API не гарантирует точное достижение целей редактирования или потокобезопасный доступ
к общему экземпляру.

Полезные будущие API включают запросы ограничений по типу/ссылке и пакетное редактирование
ограничений с явной семантикой ошибок. Измеренные потребности App могут обосновать
введение ревизий или изменений геометрии в виде дельт. Инъекция ошибок DCM улучшила бы
покрытие случаев частичного редактирования; транзакциям нужен явный проект восстановления.
Надёжная диагностика DCM остаётся будущей работой.
Жёсткое групповое перетаскивание и откат при отмене требуют дополнительной семантики
решателя и политики сеансов App. Версионированное хранение и идентичность документа остаются
вне API для работы в памяти.

SketchGTEST содержит случаи CRUD, диагностики, перетаскивания, снимков и замены состояния
для DCM, а также проверки совместимого API выбора. Поведенческие тесты, приложение,
полные сборки и CI для этого рефакторинга не запускались; поведение во время выполнения
не проверено.
